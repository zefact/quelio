Quelio ／ 機能詳細

機能詳細

Quelio が対応するデータベースのバージョンと、データベースごとに「できること」「できないこと」をまとめています。 できないことの多くは、そのデータベース自体の仕様によるもの（SQLiteのALTER TABLEの制約など）と、 Quelio が未実装のものの2種類があります。理由も併記しています。

対象バージョン: Quelio v0.6.0 最終更新: 2026-08-28 ベータ版のため今後変更されることがあります

01対応バージョン

「対応バージョン」は、Quelio が使っているクエリ・コマンドが動作する範囲です。 ベータ版のため、記載したすべてのバージョンでの網羅的な検証は行っていません。

データベース 対応バージョン 接続方法 根拠・補足
MySQL 5.7 / 8.0 / 8.4 / 9.x TCP（SSHトンネル可） 定義の取得に information_schema を使用。 EXPLAIN ANALYZE は MySQL 8.0.18 以降でのみ利用できます。MariaDB (10.x / 11.x) も接続・参照は可能ですが、動作確認は限定的です。
PostgreSQL 10 以降（12 以降を推奨） TCP（SSHトンネル可） カラム情報の取得に pg_attribute.attidentity（10で追加）を使用。 パーティションテーブルの表示も10以降です。スキーマ（search_path）に対応しています。
SQLite SQLite 3 系のデータベースファイル ファイルを直接開く エンジン（SQLite 3.51）をアプリに同梱しています。 環境に SQLite をインストールする必要はありません。存在しないファイルを指定しても新規作成はしません（打ち間違い防止）。暗号化DB（SQLCipher）は開けません。
Valkey
（Redis互換）		 Valkey 7.2 以降 / Redis 6.0 以降 TCP・TLS（SSHトンネル可） 値の更新に SET … KEEPTTL（6.0で追加）、stream の操作に XADD 系（5.0で追加）を使用。 動作確認は Valkey 8.1 で行っています。クラスタ構成・Sentinel は未対応です。

03データベース別の詳細

できないことは、理由を「DBの仕様」と「Quelio 未実装」に分けて記載しています。

MySQL

5.7 / 8.0 / 8.4 / 9.x

できること

  • テーブル定義のその場編集（カラム・インデックスの追加／変更／削除）
  • カラムのドラッグでの並べ替え（CHANGE COLUMN … FIRST / AFTER）
  • 属性の変更（AUTO_INCREMENT / ON UPDATE CURRENT_TIMESTAMP）
  • 照合順序の変更、テーブル／カラムのコメント編集
  • インデックス種別の指定（BTREE / HASH / FULLTEXT / SPATIAL）
  • 外部キーの追加・削除（ON DELETE / ON UPDATE の指定つき）
  • テーブル・データベースの作成（文字コードと照合順序を選択）
  • CSV / TSVファイルの取り込み、mysqldump / mysql を使ったエクスポート・インポート

できないこと

  • ビュー・ストアドプロシージャ・関数・トリガの編集（定義の表示はできます。未実装）
  • ユーザー・権限管理、パーティション操作（未実装）
  • 生成カラム（GENERATED）の変更 — 式が失われるため受け付けません
  • 主キー・UNIQUE制約に紐づくインデックスの変更 — 制約側の操作が必要なため
  • EXPLAIN ANALYZE は 8.0.18 未満では使えません（DBの仕様）

PostgreSQL

10 以降（12 以降を推奨）

できること

  • スキーマ付きのテーブル操作（スキーマ名.テーブル名）
  • テーブル定義のその場編集、COMMENT ON によるコメント編集
  • 接続先の pg_type から取得した型を選択（enum・ドメイン・PostGISの型も候補に出ます）
  • インデックス種別の指定（btree / hash / gist / gin / spgist / brin）
  • 外部キーの追加・削除、スキーマ・データベースの作成／削除
  • パーティションの表示（CREATE 文・ALTER 文の生成にも PARTITION BY / PARTITION OF を反映）
  • EXPLAIN / EXPLAIN ANALYZE、CSV取り込み、pg_dump / psql 連携

できないこと

  • カラムの並べ替え — PostgreSQL 自体が対応していません（DBの仕様）
  • 照合順序だけを変える構文が無いため、型の指定とまとめて実行します（DBの仕様）
  • ビュー・マテリアライズドビューの定義編集、REFRESH（未実装。一覧表示と削除は可能）
  • 関数・トリガの編集（定義の表示はできます。未実装）
  • 拡張機能・ロール／権限の管理（未実装）

SQLite

SQLite 3 系のファイル（エンジン同梱: 3.51）

できること

  • ファイルを選ぶだけで接続（サーバー・追加インストール不要）
  • テーブルの作成・改名・削除、カラムの追加・削除・改名
  • インデックスの追加・変更・削除、データの編集、CSV / TSVの取り込み
  • 名前・値からの検索、トリガの定義表示、CREATE 文の表示
  • ER図・スキーマ比較・定義書CSV・EXPLAIN QUERY PLAN
  • 主キーが無いテーブルでも、rowid による主キーがあれば編集できます

できないこと

  • 型・NOT NULL・デフォルトの変更 — SQLite の ALTER TABLE ではできず、テーブルの作り直しが必要（DBの仕様。将来対応を検討）
  • コメント（日本語の論理名） — 仕組みがありません（DBの仕様）
  • 照合順序の変更・インデックス種別の指定（DBの仕様）
  • 外部キーの追加・削除 — 作成後に付け外しできません（DBの仕様。表示は可能）
  • 概算行数の表示 — 統計情報がありません（DBの仕様）
  • エクスポート／インポート（外部ツール連携）（未実装）
  • 暗号化DB（SQLCipher）、ATTACH した複数DBの表示（未実装）

Valkey（Redis互換）

Valkey 7.2 以降 / Redis 6.0 以降

できること

  • キーの一覧（SCAN によるパターン絞り込み）と、型・TTL・メモリ使用量の表示
  • 値の表示（string / hash / list / set / zset / stream）と、JSON・PHPシリアライズの整形表示
  • 値の編集・要素の追加・削除、キーの作成・改名・削除、TTLの変更
  • キーの検索（値の中身・キー名）と、パターンに一致するキーの一括削除
  • コマンドコンソール（redis-cli 風の出力・複数行実行・結果のキャプチャ）
  • TLS接続（SNI指定つき）と SSHトンネル

できないこと

  • クラスタ構成・Sentinel — 単一ノードへの接続のみ（未実装）
  • 値ビューは先頭200件まで、string は先頭4096バイトまで（それ以降はコンソールから）
  • バイナリの値・長すぎる値の編集 — 壊さないよう禁止しています
  • stream の既存エントリの変更 — 仕様上できません（追加・削除は可能）
  • Pub/Sub・MONITOR — 接続を占有するためブロックしています
  • COPY / DUMP / RESTORE、ACL・ユーザー管理（未実装）
  • フィールド単位のTTL（HEXPIRE 系）、JSON などモジュール型の値表示（未実装）

04すべての接続に共通する制限

項目内容
読み取り専用モード 接続ごとに「読み取り専用」を指定できます。指定すると、SQLの更新系・DDL・行編集・Valkeyの書き込みコマンド・SQLファイルの取り込みをすべて拒否します。画面側でも変更操作を出さず、タブに R/O バッジを表示します。
取り返しのつかないSQLの確認 DROP / TRUNCATE や WHERE の無い UPDATE / DELETE は、実行前に接続先とSQLを出して確認します。ALTER / RENAME の確認は 設定 > 一般 で外せます（マイグレーション用のSQLをまとめて流すとき向け）。
画面に出す件数・文字数 結果は1000行ずつ、1セルあたり1000文字までの表示です。CSV出力はそのSQLの全行、EXPLAIN は全文を表示します。
TLSの検証 MySQL / PostgreSQL は接続ごとにTLSの使い方を選べます（既定 / 使わない / 必須 / CA検証 / CA+ホスト名検証）。CA証明書とクライアント証明書のファイルも指定できます。SSH踏み台を経由する場合は接続先が 127.0.0.1 になるため、ホスト名の検証はできません（CA証明書の検証までを行います）。
対応OS・言語 macOS（Apple Silicon）／ Windows（x64）。UIは日本語のみです。
